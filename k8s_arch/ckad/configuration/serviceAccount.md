---

generates an access token in a secret object upon creation.

**sa workflow:**

- create serviceAccount
- generate access token secret (if necessary)
- mount token as volume to pods.

**after v1.22:** serviceAccounts no longer rely on secret tokens. tokens are generated by the **TokenRequestAPI** and are:

- audience bound
- time bound
- object bound

**before v1.24:** [**serviceAccount** [**secret** [**token**(doesn't expire)]]]
**after v1.24:** [**serviceAccount** [**token**(default expire after 1h)]]

**Documentation**:

- Service account token Secrets:
  https://kubernetes.io/docs/concepts/configuration/secret/#service-account-token-secrets
- Managing Service Accounts:
  https://kubernetes.io/docs/reference/access-authn-authz/service-accounts-admin/

### Create ServiceAcounts and Secrets

create an access token in a secret object **after v1.24**:
_serviceAccount must be created first_

```bash
# expires after 1 hour
kubectl create token jenkins-sa
```

```yaml
# doesn't expire
apiVersion: v1
kind: Secret
type: kubernetes.io/service-account-token
metadata:
  name: jenkins-sa
  annotations:
    kubernetes.io/service-account.name: jenkins-sa
```

see sa token

```bash
kubectl describe serviceaccount jenkins-sa | grep -i token

jq -R 'split(".") | select(length > 0) | .[0],.[1] | @base64 | fromjson' <<< <secret_token>
```

### Use ServiceAccounts

use sa token

    curl htts://192.168.56.70:6443/api -insecure \
    --header "Authorization: Bearer <sa_access-token>"

configure sa in a pod

    apiVersion: v1
    kind: Pod
    metadata:
      ...
    spec:
      containers:
        - name:
          ...
      serviceAccountName: jenkins-sa

disable default sa automount

    apiVersion: v1
    kind: Pod
    metadata:
      ...
    spec:
      containers:
        - name:
          ...
          automountServiceAccountToken: false
